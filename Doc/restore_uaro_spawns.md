# Восстановление оригинальных uaRO-спавнов мобов

## Проблема
На сервере «потерялись» оригинальные размещения мобов: активным был только
официальный набор `npc/mobs/` (через `scripts_monsters.conf`), а кастомные
uaRO-спавны `npc/mobs_uaro/` **не грузились**.

Причина — не перезапись в git (на ветке x64 файлы `npc/mobs/` и
`npc/mobs_uaro/` не менялись со старта ветки), а сломанная загрузка:
`scripts_main.conf` импортирует `npc/scripts_monsters_uaro.conf`, но файл на
диске назывался `scripts_monsters_uaro.conf_` (с подчёркиванием = отключён).

## Решение
Включить uaRO-набор обратно рядом с официальным, но без задвоения мобов.

**Правило (выбор владельца сервера): на пересечении побеждает uaRO.**
- Для каждой пары `(карта, ID моба)`, которая есть и в `npc/mobs/`, и в
  `npc/mobs_uaro/{fields,dungeons}` — остаётся uaRO-плотность/размещение,
  официальные строки удаляются.
- Официальный набор остаётся только как **заполнитель**: пары `(карта, ID)`,
  которых нет в uaRO, сохраняются нетронутыми.
- uaRO-only мобы возвращаются просто включением uaRO-конфига.
- Спец-добавки `*_uaro.txt` (напр. `c_tower_uaro.txt` — тактические Punk/Clock)
  **аддитивны**, в ключ дедупликации не входят, стакаются поверх.
- `citycleaners.txt` / `pvp.txt` / `airplane.txt` uaRO остаются
  закомментированы (как в оригинальном uaRO-конфиге); их официальные версии
  не трогаются.

## Изменения
1. `dumps/forge/restore-uaro-spawns.py` — генератор дедупликации (идемпотентный,
   `--dry-run` по умолчанию, `--apply` пишет). Строит набор `(карта, ID)` из
   загружаемых uaRO-файлов (`fields/` + `dungeons/`, без `*_uaro.txt`) и
   вырезает из `npc/mobs/**/*.txt` все пересекающиеся строки monster/boss_monster.
2. `npc/mobs/**/*.txt` — удалено **2491** пересекающихся строк спавна в 46 файлах
   (uaRO побеждает); оставлена **801** строка-заполнитель.
3. `npc/scripts_monsters_uaro.conf_` → `npc/scripts_monsters_uaro.conf`
   (переименование = включение; импорт в `scripts_main.conf:62` теперь резолвится).
4. `npc/scripts_monsters.conf` — убран дублирующий include
   `npc/mobs_uaro/dungeons/c_tower_uaro.txt` (теперь грузится через uaRO-конфиг;
   иначе спец-мобы грузились бы дважды).
5. `npc/mobs_uaro/dungeons/moc_pyrd.txt` → `moc_pryd.txt` — исправлена опечатка
   в имени файла (uaRO-конфиг ссылался на правильное `moc_pryd.txt`, иначе
   спавны Пирамиды Морока не загрузились бы).

## Итог (статическая проверка)
- Активных уникальных `(карта, ID)`: **2035** (было 1874 только-официальных).
- Двойная загрузка `(карта, ID)` официальный∩uaRO-база: **0**.
- Все uaRO-карты (225) и официальные карты (136) присутствуют в
  `conf/maps_athena.conf` — спавны не теряются из-за отсутствующих карт.
- Все ID мобов в uaRO-файлах есть в `mob_db`, **кроме одного**.

## Известный нюанс (изначальный uaRO)
`npc/mobs_uaro/fields/payon.txt`: `pay_fild06 ... Thief Bug Female 1017,40` —
моба с ID **1017** нет в `mob_db` (пробел между 1016 и 1018; настоящая Thief Bug
Female = 1053). Это ошибка данных самого uaRO (в официальном наборе строки не
было). Строка оставлена как есть для точного восстановления оригинала; сервер
пропустит её с предупреждением (не `[Error]`). При желании можно поправить
ID на 1053 или закомментировать строку.

## Перегенерация
```
python3 dumps/forge/restore-uaro-spawns.py --root . --apply
```
Идемпотентно: повторный запуск удаляет 0 строк (пересечение уже убрано).
