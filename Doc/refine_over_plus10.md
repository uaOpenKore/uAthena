# Заточка выше +10 (до +99) для игроков [refine99]

Расширение штатной заточки за +10 (до +99) **для игроков**, через обычный NPC-рефайнер.
Канон +0..+10 (таблица `db/refine_db.txt` и бонус ATK/DEF) **не тронут** — всё выше +10
управляется формулами и конфигом, без раздувания таблиц и NPC-скриптов.

Это развитие GM-only PoC (`Doc/refine_gm99_poc.md`): тот дал `@refine`/`@item` до +99 для ГМ;
здесь добавлены шансы, баланс бонуса и игроцкий путь через рефайнера.

## Принцип «универсально и не огромно»

- **Таблица `refine_db.txt` остаётся 5×10** (Armor + Lv1-4, заточка 0..10). Никаких 99 строк.
- **Массивы `percentrefinery[5][11]` / `refinebonus[5][3]` не меняются.** «Хвост» +11..+99 —
  это две маленькие функции в движке:
  - `status_refine_chance(wlv, refine)` (status.c) — шанс успеха;
  - `status_refine_bonus(per_level, refine)` (status.c) — бонус ATK/DEF.
- **NPC-скрипт уже был циклом** (`function refinemain` в `npc/merchants/refine.txt`): он не
  перечисляет уровни, а крутит «текущий → +1», спрашивая шанс у движка. Поэтому правки в нём —
  **ровно 2 строки**: хардкод предела `10` заменён на `getbattleflag("refine_player_max")`.
- Всё поведение задаётся ~6 флагами `conf/battle/items.conf`. `refine_player_max: 10` полностью
  выключает фичу (чистый ванилла).

## Что именно меняется выше +10

| Аспект | +0..+10 | +11..+99 |
|--------|---------|----------|
| Шанс успеха | таблица `refine_db.txt` (канон) | формула: `chance = base − step·(lvl−10)`, не ниже `min` |
| Бонус ATK/DEF | `refine · per_level` (канон) | `10·per_level + (refine−10)·(per_level · bonus_percent/100)` |
| Провал | предмет уничтожается (канон) | настраивается: уничтожить / −1 уровень / оставить |
| Доступ | NPC + кузнец (скилл) | только NPC-рефайнер; ГМ — `@refine`/`@item` |

`WS_WEAPONREFINE` (скилл кузнеца) **намеренно оставлен на +10** — это отдельная, ограниченная
уровнем скилла механика; путь до +99 — это NPC-рефайнер (Холленгрен и компания).

## Флаги (conf/battle/items.conf), дефолты

| Флаг | Деф. | Смысл |
|------|------|-------|
| `refine_player_max` | 99 | предел заточки игроком через NPC (хард-потолок 99; `10` = выкл) |
| `refine_over_chance` | 20 | шанс % первого шага +10→+11 |
| `refine_over_chance_step` | 1 | сколько % отнимать за каждый следующий уровень |
| `refine_over_chance_min` | 5 | нижний предел шанса |
| `refine_over_bonus_percent` | 50 | бонус за уровень выше +10, в % от канон-бонуса (100=полный, курбит линейный взрыв) |
| `refine_over_fail` | 1 | провал выше +10: 0=уничтожить, 1=−1 уровень, 2=оставить |

Менять баланс можно прямо в conf без пересборки. ГМ `@refine`/`@item` всегда бьют до +99
независимо от `refine_player_max`.

## Пример (Lv4 оружие: per_level=7, over=13, safe=4)

- +10: ATK +70 (канон). +99 при `bonus_percent=50`: 70 + 89·3 = **+337** (вместо линейных +693).
- Шанс при дефолтах: +10→+11 = 20%, далее −1%/ур., пол 5% (т.е. с +14 и выше ≈ 5%).
  Достичь +99 чистым РНГ практически нереально — это крайний гринд/слот для богатых.

## Корректность

При `refine ≤ +10` все пути **байт-в-байт** прежние (формулы расходятся только выше +10):
бонус, `getequippercentrefinery`, `failedrefitem` (уничтожение для +0..+10 не изменено).
Хранилище/БД/сеть несут +99 (см. `refine_gm99_poc.md`): `char`/`tinyint unsigned`/`word`.
Существующие предметы выше +10 сохраняют свой (курбленный) бонус даже если позже выставить
`refine_player_max: 10` — потолок ограничивает только НОВУЮ заточку.

## Изменённые файлы

- `src/map/status.c` — `status_refine_chance` + `status_refine_bonus`; двухсегментный бонус оружия/брони.
- `src/map/status.h` — прототип + обновлён комментарий `MAX_REFINE_GM`.
- `src/map/script.c` — `getequippercentrefinery` (формула + потолок 99), `successrefitem` (кламп 99),
  `failedrefitem` (настраиваемый провал выше +10).
- `src/map/battle.c` / `battle.h` — 6 флагов `refine_*` (таблица + дефолты + структура).
- `conf/battle/items.conf` — блок настроек с комментариями.
- `npc/merchants/refine.txt` — 2 гейта `10` → `getbattleflag("refine_player_max")`.

## Тестирование (нужен клиент — на тестерах)

1. Игрок у рефайнера: заточить экип за +10 (тратит Oridecon/Elunium + зени), увидеть шанс/провал.
2. Проверить провал: при `refine_over_fail: 1` предмет должен падать на −1, не исчезать.
3. ГМ `@refine 2 99` / `@item <id> 1 1 99` — мгновенно +99.
4. Бонус ATK/DEF на высоких уровнях — оценить баланс, подкрутить `refine_over_bonus_percent`.
5. Клиент 2007/PV7 уже подтверждён рисует +99 (см. PoC).
