# Полный бекпорт окон Аренды и Мерка (под доработку клиента)

Ветка: `x64`. Задача: довести серверную поддержку клиентских окон аренды и
наёмника, чтобы доработанный клиент мог их показывать.

## Стратегия (утверждена)
Доработанный клиент будет объявлять **высокий `packet_ver` (≥ 21)**. Сервер шлёт
оконные пакеты **только** таким клиентам (runtime-гейт по `sd->packet_ver`).
Ванильный клиент 2007 (packet_ver 7) не получает их → **десинка нет**.
PACKETVER компиляции НЕ поднимаем (текущий 2007-клиент работает как прежде).

## Аренда — уже было полным, не трогали
`clif_rental_time` (0x298) и `clif_rental_expired` (0x299) реализованы и
вызываются:
- `pc.c` (на логине: истёкшие удаляет, по активным шлёт счётчик),
- `script.c` (`rentitem` при выдаче).
Пакеты старые, известны и PV7, и старшим версиям (каскад packet_db). Менять
нечего.

## Мерк — основная работа
Функции окна были обёрнуты в `#if PACKETVER >= 20080102` (PACKETVER=7) →
компилировались в пустышки. Сделано:

1. **Сняты компайл-гейты** с `clif_mercenary_info` (0x29b), `_updatestatus`
   (0x2a2), `_skillblock` (0x29d), `_message`. Вместо них — **runtime-гейт**
   `if (sd->packet_ver < PACKETVER_MERC_WINDOW) return;`, где
   `PACKETVER_MERC_WINDOW = 21` (версия, с которой в packet_db появляется 0x29b).
2. **Добавлен `clif_msg`** (ZC_MSG `0x291`) — его в uAthena не было, а
   `clif_mercenary_message` его зовёт; свой гейт `packet_ver < 20`.
3. **Добавлен парсер `clif_parse_mercenary_action`** (CZ_MER_COMMAND `0x29f`):
   `option == 2` → `merc_delete(md, 2)` (кнопка «уволить» в окне). Зарегистрирован
   в парс-таблице (`{clif_parse_mercenary_action,"mermenu"}`) и привязан в
   `db/packet_db.txt` (`0x029f,3,mermenu,0`).

Вызовы окна уже стояли (`mercenary_soldier.c`: summon → info+skillblock,
HP/SP/faith → updatestatus, message) — теперь оживают для capable-клиентов.

### Файлы
- `src/map/clif.c` — ungate + `clif_msg` + `clif_parse_mercenary_action` + запись
  в парс-таблице.
- `src/map/clif.h` — объявления `clif_msg`, `clif_parse_mercenary_action`.
- `db/packet_db.txt` — `0x029f` → `mermenu`.

## Механика (почему работает)
- `packet_db` грузится для всех версий 0–22, длины каскадируют →
  `packet_len(0x29b)=72` (берётся по `clif_config.packet_db_ver`, default
  `MAX_PACKET_VER=22`). Сервер шлёт корректную длину.
- `sd->packet_ver` — версия, заявленная клиентом при коннекте. Доработанный
  клиент должен слать connect версии ≥ 21, чтобы детектиться как ≥ 21 и получать
  окно. Это часть доработки клиента.

## Проверка
- `make sql` — чистая сборка (тела merc-функций скомпилированы впервые,
  все символы разрешились).
- `--run_once` boot-parse — `packet_db.txt` грузится с привязкой `mermenu`
  без ошибок, сервер доходит до "ready", выходит без утечек. Новых `[Error]` нет.
- Рантайм окон — на доработанном клиенте (packet_ver ≥ 21) за тестерами.

## Что НЕ делали
- Не поднимали компайл-PACKETVER (это сломало бы 2007-клиент).
- Окно мерка показывает данные «как в eAthena»; дальнейшая логика боя мерка
  (M7d из mercenary-soldier-port) — отдельная отложенная задача.
