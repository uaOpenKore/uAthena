нужна система автоконфигурирования мап-серверов.
- скрипт запускается раз в месяц и конфигурирует списки карт maps_athena.conf для мап-серверов confN
- скрипт должен по /opt/uathena/confN - определять количество мап-серверов (чанков)
- скрипт должен брать список локаций из файла /opt/uathena/conf/maps_athena.conf
- скрипт должен распеделять по мап-серверам нагруженные, и ненагруженные локации, по следующему принципу:
-- списки формируются новые при запуске, старые не интересуют уже, на момент запуска скрипта
-- выбрать из базы системы мониторинга 1 локацию с самым большим пиком игроков и с самым маленьким (желательно нулевым - но таких в базе мониторинга быть не должно), и записать эти 2 локации в conf1/maps_athena.conf. Эти 2 локации исключаются из общего списка.
-- следующая итерация выборки пишется в conf2/maps_athena.conf
-- следующая итерация выборки пишет в следующий чанк, и так по кругу, пока весь общий список не опустеет.
-- если в общем списке остаются локации (а там могут остаться локации, на которые вообще никто не заходил) - то такие локации по одной штуке разбросать равномерно по всем чанкам
+ таким образом мы приблизительно должны равномерно распределить локации по мап-серверам, что даст некую равномерную нагрузку по мап серверам
-- скрип автоконфигурирования должен брать статистику за последние 6 недель, из почасовой статистики (сверх высокая точность тут не нужна, а достаточно общего понимания общего количества пиков по локациям) - нагрузка не будет равномерной и идеальной, и этого не требуется, главное что мы имеем некую статистическую равномерность

- скрипт срабатывает по крону в 1 час ночи каждого 1го числа, каждого месяца
+а в 2 часа ночи будет срабатывать скрипт перезапусков мап серверов
