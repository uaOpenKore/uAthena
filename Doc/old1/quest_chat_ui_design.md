# Дизайн: чат-интерфейс квестов (@quests / @quest) — обход отсутствия окна журнала в PV7

Дата: 2026-06-15. Ветка: `x64`. Поверх движка quest-лога SP2 (`doc/backport_sp2_questlog_design.md`).

Клиент тестировщиков (2007-05-07a, PACKETVER 7) **не имеет окна журнала квестов**. Движок SP2 хранит
состояние квестов, но игрок его не видит. Эта фича выводит журнал в **чат** через atcommand'ы — чистый
обход ограничения клиента, без правок клиента/PACKETVER.

## 1. Команды (доступ игрокам, atcommand level 0)

### `@quests` — список квестов
Выводит квесты игрока. **Порядок: сначала завершённые, потом активные/неактивные** — так активные
оказываются внизу чата (видны без прокрутки; завершённых обычно много). Каждая строка пронумерована
`[1..N]` **в порядке вывода** — это короткий **id** для `@quest`.
```
--- Квесты (вып.) ---
[1] 1002 "Job Change to Acolyte" — выполнен
...
--- Квесты (актив.) ---
[8] 1011  "..." — активен, без лимита
[9] 60214 "Hunting Porings" — активен, ост. 2ч13м | Poring 3/10, Lunatic 0/5
@quest <N> — подробно, @quest <N> cancel — отменить
```
Данные: `sd->quest_log[]` (state/time/count), `sd->quest_index[]`→`quest_db[]` (имя/цели),
`mob_db(id)->jname` (имена мобов). Пустой список → «Квестов нет».

### `@quest <N>` — подробности
N — короткий id из `@quests` (позиция в выводе). Показывает: id квеста, имя, статус, точное оставшееся
время (или «истёк»), каждую цель отдельной строкой `<моб>: <тек>/<нужно>`, подсказку про cancel.
Неверный N → «Нет квеста с таким номером, наберите @quests».

### `@quest <N> cancel` — отмена
Отменяет **любой** квест (включая завершённый — игрок может сбросить и пройти заново ради доступа).
`quest_delete(sd, quest_id)` + сообщение в чат. **Без доп. подтверждения** — набор слова `cancel`
является подтверждением. (Ключевое слово ASCII `cancel` — кириллица в аргументах под PV7 ненадёжна по
кодировке; при желании позже добавим алиас.)

## 2. Доработка движка SP2 (имена квестов)
`quest_db.txt` уже содержит имя 9-м полем (`...,"Transcend"`), но `s_quest_db` его не хранит (поле
закомментировано). Включаем: добавить `char name[NAME_LENGTH]` (или чуть больше) в `s_quest_db` и парсить
имя в `quest_read_db` (9-е поле в кавычках). Аддитивно, существующее поведение не меняется. Имя нужно
для @quests/@quest (окно PV7 его всё равно не показывает; клиентских questid2display у сервера нет).

## 3. Архитектура

- `src/map/atcommand.c` — 2 новые `ACMD_FUNC`: `atcommand_quests` (список), `atcommand_quest`
  (детали/cancel; парсит `<N> [cancel]` из `message`). Вывод — `clif_displaymessage(fd, buf)` построчно
  (идиома `@mobinfo`). Регистрация в таблице atcommand + объявление.
- `conf/atcommand_athena.conf` — `quests: 0` и `quest: 0` (уровень доступа игрока).
- `src/map/quest.c`/`quest.h` — добавить `name` в `s_quest_db` + парс; (опц.) хелпер
  `quest_display_index → quest_log idx` держим прямо в atcommand (просто, без API движка).
- Существующие команды/NPC/движок SP2 — без изменений (только добавления).

Маппинг id→квест: `@quests` нумерует строки в порядке вывода (вып.→актив.); `@quest <N>` берёт N-й по
тому же порядку. В пределах одного просмотра стабильно; после отмены/выполнения — перезапустить `@quests`.

## 4. Безопасность/корректность
- Доступ level 0, но команды трогают только `sd` вызывающего игрока (свой quest_log) — не чужой.
- `cancel` зовёт существующий `quest_delete` (движок SP2) — корректно снимает квест и помечает save_quest.
- Буферы вывода фиксированы (`CHAT_SIZE`/snprintf) — без переполнений; имена мобов/квестов усечены.
- Без правок клиента/PACKETVER.

## 5. Верификация
- `make sql` чисто (map). Standalone-проверка парсера имени (или boot-лог `Done reading ... quest_db.txt`).
- На кластере (тестировщики): `@quests` показывает имена/цели/время; `@quest N` — детали; `@quest N cancel`
  снимает; перезаход — изменения сохранились; недоступно влиять на чужие квесты; действующие команды целы.

## 6. Дорожная карта «обход клиента через chat» (одобрено, очередь — после этой фичи)
- **Нотификация прогресса цели в чат** при убийстве моба (`quest_update_objective` → `@`-стиль сообщение
  «Poring 3/10») — та же подсистема, естественный второй шаг.
- **`@status` / кулдауны** — точное оставшееся время баффов и задержек скиллов (клиент рисует иконки, не секунды).
- **`@whereis <моб>` / поиск NPC** — где водится/дропает; клиент не умеет поиск.
- **`@market <item>`** — поиск по вендорам/ценам (аналог searchstores; нет UI в PV7).
- **Достижения/титулы** — нет UI в PV7 (нужен небольшой движок) → чат.
- **Награды за онлайн/ежечасные** — чат-выдача.

## 7. Будущий SP: наёмники (Mercenary Soldier)
