# Дизайн: нотификация прогресса квеста в чат

Дата: 2026-06-15. Ветка: `x64`. Поверх движка SP2 + chat-UI (`doc/quest_chat_ui_design.md`).
Следующий пункт одобренной дорожной карты «обход клиента через chat»: клиент PV7 не всплывает обновление
цели квеста — выводим прогресс в чат.

## Поведение

В `quest_update_objective` (quest.c, сразу после инкремента `count[j]`) — по `battle_config.quest_progress_notify`:
- **0** — ничего (исходное поведение движка).
- **1** — на каждое зачётное убийство: `[Quest] <моб>: <тек>/<нужно> (<имя квеста>)`.
- **2** — только когда цель заполнилась (`тек >= нужно`): `[Quest] <моб>: <нужно>/<нужно> done (<имя квеста>)`.

Дополнительно (режимы 1 и 2): когда инкремент заполнил **последнюю** незавершённую цель квеста (все цели
готовы) — строка `[Quest] "<имя>" - all objectives complete!`.

Вывод — `clif_displaymessage(sd->fd, buf)`, метки **ASCII English** (клиент 2007 докодовый; имена моба
(`mob_db()->jname`) и квеста (`quest_db[].name`, из chat-UI доработки) — английские из данных). RU — позже
через `msg_txt`.

## Компоненты (только добавления)
- `src/map/battle.h` — `int quest_progress_notify;` в структуре `battle_config`.
- `src/map/battle.c` — `{ "quest_progress_notify", &battle_config.quest_progress_notify }` в таблице конфигов
  (формат uAthena — 2-полевой: имя+указатель); дефолт **2** ставится через механизм значений по умолчанию
  uAthena (как у прочих battle_config — определить точное место в плане). Диапазон 0..2 (значения вне —
  трактуются как 1: «не 0 и не 2»; некритично).
- `conf/battle/misc.conf` — `quest_progress_notify: 2` с комментарием (документация настройки).
- `src/map/quest.c` — блок нотификации в `quest_update_objective` под `if( battle_config.quest_progress_notify )`.
- Существующее поведение/команды/NPC/движок — без изменений.

## Логика блока (псевдо)
```
count[j]++; save_quest=true; clif_quest_update_objective(...);   // как сейчас
if( battle_config.quest_progress_notify ) {
    reqd = quest_db[idx].count[j]; cur = quest_log[i].count[j]; mb = mob_db(mob);
    if( battle_config.quest_progress_notify == 1 || cur >= reqd )
        // строка прогресса/выполнения цели
    if( cur >= reqd && <все цели quest_db[idx] заполнены> )
        // строка "all objectives complete"
}
```

## Корректность/безопасность
- Вызов из `mob_dead`-хука (SP2) для каждого зачётного игрока → каждый видит свой прогресс. Игровой поток,
  один лёгкий чат-пакет на зачётное убийство (даже в режиме 1 — пренебрежимо).
- Буферы фиксированы (snprintf), имена усечены; `mob_db()` не возвращает NULL (mob_dummy).
- API/инвариант: только новое поле конфига + локальный блок; ничего существующего не меняется.

## Верификация
- `make sql` чисто; boot-smoke (quest_db читается, без утечек); диапазон конфига 0..2.
- На кластере (тестировщики): `=1` — строка на убийство; `=2` — только при заполнении цели + «all objectives
  complete»; `=0` — тихо; прогресс сохраняется (SP2).
