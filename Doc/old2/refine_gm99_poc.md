# Заточка до +99 (GM-only, proof-of-concept)

Эксперимент: проверить возможность заточки экипировки выше штатного +10 — **только через
GM-команды**, без переделки основной механики заточки.

## Что сделано (минимальный диф)

- Новая константа `MAX_REFINE_GM 99` (`src/map/status.h`) рядом с `MAX_REFINE 10`.
- `@refine` (`atcommand.c`, GM lvl 60) — потолок поднят с `MAX_REFINE` до `MAX_REFINE_GM`.
- `@item` (`atcommand.c`, GM) — потолок refine поднят с жёсткой `10` до `MAX_REFINE_GM`
  (чтобы можно было сразу выдать заточенный предмет для теста) + защита от отрицательного refine.

**`MAX_REFINE 10` НЕ менялся.** Все обычные пути по-прежнему стопаются на +10:
NPC-заточка, скилл кузнеца `WS_WEAPONREFINE`, таблица шансов `percentrefinery`,
скриптовые `successrefitem` / `downrefitem`, проверки `getrefine`-логики. То есть для
обычных игроков ничего не изменилось — заточка выше +10 доступна исключительно ГМ.

## Почему +99 проходит сквозь все слои (разбор feasibility)

| Слой | Тип | Максимум | +99 |
|------|-----|----------|-----|
| C-структура `struct item.refine` (map и char) | `char` | 127 | ✅ |
| Колонка БД `refine` (inventory/cart/storage/guild_storage) | `tinyint(3) unsigned` | 255 | ✅ |
| Пакет `clif_refine` (эффект заточки) | `WFIFOW` (16 бит) | 65535 | ✅ |
| Пакеты предметов (списки/экип) | `WFIFOB`/`WBUFB` (байт) | 255 | ✅ |
| Бонус заточки (`status.c`) | линейно `refine * refinebonus[wlv]` | индекс по уровню оружия, не по refine | ✅ нет выхода за массив |
| Сохранение/загрузка на char-сервере | `sprintf`/`atoi`, без clamp | — | ✅ переживает автосейв |

Краша нет: бонусные массивы индексируются уровнем оружия (`wlv`, clamp до 4), а не уровнем
заточки. Таблица шансов `percentrefinery[5][MAX_REFINE+1]` индексируется по refine, но её
дёргают только обычные пути, которые сами не идут выше +10 → выхода за границы нет.

**Схема БД менять не нужно** — `tinyint unsigned` уже вмещает 0..255.

## Как тестировать (на ГМ-аккаунте)

```
@refine <позиция> <+кол-во>     # напр. @refine 2 99  → правая рука до +99
@item <id> 1 1 99               # выдать предмет сразу с refine 99 (id name amount identify refine)
```
Позиции экипа для `@refine` — стандартные битовые маски (`@help refine`).

## Что именно проверяем (единственное неизвестное — клиент)

Сервер несёт +99 полностью. Открытый вопрос — **как клиент 2007/PV7 рисует заточку выше
+10/+15**: цифра в названии предмета, иконка, окно апгрейда. Это и есть цель проверки —
оценивается в игре с клиентом.

Побочный эффект (ожидаемый, механику не трогали): бонус ATK/DEF и item-скрипты с
`getrefine()` масштабируются линейно — на +99 значения будут очень большими. Для проверки
возможности это нормально; балансом займёмся отдельно, если фичу решат оставить.

## Как откатить / выключить

Вернуть в `@refine`/`@item` потолок `MAX_REFINE_GM` → `MAX_REFINE` (и `10` в `@item`),
пересобрать map-сервер. Либо `#define MAX_REFINE_GM 10` в `status.h` — мгновенно вернёт
штатное поведение без правки команд. Уже заточенные выше +10 предметы при этом останутся
в БД с прежним значением (clamp при заточке, не при загрузке).
