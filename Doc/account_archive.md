# Архив неактивных аккаунтов (SQL-версия)

С 22.11.2026 чар-сервер сам переносит давно не заходивших игроков в архивные таблицы, а при входе игрока с верным
логином и паролем возвращает его обратно.

## Кого переносим
- аккаунты игроков: `account_id >= 2000000`, кроме служебных (`sex = 'S'`);
- `lastlogin` старше `account_archive_days` (365) дней; если игрок ни разу не заходил, то регистрация (`login.created`)
  старше этого срока. Старые аккаунты без даты регистрации и без входа переносятся сразу;
- GM и забаненные тоже;
- только оффлайн: не в игре, не в выборе персонажа, без открытой лавки автотрейда.

## Что происходит при переносе
- В архив копируются: строка `login`, склад, переменные аккаунта и персонажей, персонажи, инвентарь, тележка,
  скиллы, точки варпа (memo), хоткеи, друзья, квесты, ачивки, питомцы, гомункул и его скиллы.
- Из рабочих таблиц персонаж убирается так же, как при удалении:
  - выходит из пати;
  - **мастер → гильдия распускается** вместе со складом, остальные просто выходят из гильдии;
  - супруг «разводится» (кольца у него удаляются);
  - у других игроков персонаж пропадает из списка друзей;
  - наёмник и бафы (`sc_data`) не сохраняются.
- В лог чар-сервера пишется `[ARCHIVE] archived aid=… userid=… chars=… [Имя/класс/уровень] arc_no=…`.

## Таблицы
Чар-сервер создаёт их сам при старте (миграций нет):
- `arc_index` — одна строка на каждый перенос: `arc_no`, `account_id` (старый), `userid`, `lastlogin`,
  `archived_at`, `state` (0 копируется, 1 в архиве, 2 возвращён, 3 возврат прервался), `new_aid`, `restored_at`, `chars`;
- `arc_<таблица>` — копии рабочих таблиц (`arc_login`, `arc_char`, `arc_inventory`, …) с колонкой `arc_no`,
  без уникальных ключей. Старые ID в них — просто метки внутри записи, один и тот же старый ID может встречаться
  в разных переносах. `arc_login.arc_new_aid` — новый ID после возврата.

## Возврат
- Вход с логином, которого нет в `login`, но есть в `arc_login`, и с **верным паролем**: логин-сервер возвращает
  строку аккаунта с **новым account_id**. Неверный пароль — обычная ошибка, засчитывается в защиту от перебора.
- При подключении к выбору персонажа чар-сервер возвращает персонажей с **новыми ID**: со всем, что было
  перенесено, и склад аккаунта. **Без гильдии, пати, супруга и семьи.** Питомцы и гомункул получают новые ID; яйца
  и подписи создателя на вещах самого игрока переписываются на новые ID (на вещах у других игроков подпись пропадёт).
- Если имя персонажа за это время занято, он вернётся как `Имя_1` (в логе предупреждение).
- Если возврат прервался на середине (`state = 3`), второй раз он сам не запускается: разобрать вручную.

## Логины и имена из архива заняты
- регистрация через сервер (_M/_F) логина из архива запрещена; создать персонажа с именем из архива нельзя;
- **сайт при регистрации должен проверять и `login`, и `arc_login`**:
  `SELECT 1 FROM arc_login WHERE userid = ?` — иначе архивный игрок не сможет вернуться (новый аккаунт победит).

## Настройки (`conf/char_athena.conf`)
| ключ | по умолчанию | что |
|---|---|---|
| `account_archive_mode` | 2 | 0 выкл, 1 только раз в сутки писать в лог, кого бы перенёс, 2 переносить |
| `account_archive_days` | 365 | дней без входа |
| `account_archive_hour` | 5 | в какой час ночи работать (-1 = в любой) |
| `account_archive_batch` | 10 | аккаунтов за один проход |
| `account_archive_interval` | 60 | секунд между проходами |

Тест: ветка `tests`, `sqlaudit/archive_e2e.py`.
