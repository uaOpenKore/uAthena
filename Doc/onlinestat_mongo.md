# Статистика онлайна в MongoDB

Char-сервер (только ветка SQL) считает, сколько минут каждый персонаж провёл в игре и сколько минут оплатил, и пишет это в MongoDB для сайта. В SQL эти данные не попадают.

## Что считается

- **online.** Раз в минуту char-сервер смотрит, кто сейчас на карте, и каждому прибавляет 1 минуту к текущей дате. Торговцы на автотрейде не считаются. Точность ±1 минута на сессию. Минута относится к дате, в которую её увидели: полночь делит время сама.
- **paid_buy.** Минуты, выкупленные `@buyplaytime`. Map-сервер сообщает о каждой покупке пакетом 0x2b28.
- **paid_auto.** Минуты, оплаченные `@autopay`.

`online` не зависит от лимита времени. `char.play_minutes` уменьшается при покупке и не растёт при `@autopay`, а `online` всегда остаётся чистым временем в игре.

## Как данные попадают в Mongo

1. Основной поток char-сервера раз в минуту добавляет суммы в очередь в памяти и никогда не ждёт Mongo.
2. Рабочий поток раз в `onlinestat_interval` секунд (600) дописывает очередь в файл `log/online_spool.jsonl`, затем заливает весь файл в Mongo (`$inc`, upsert) и очищает его.
3. Mongo недоступна → файл растёт, повтор каждые 30 с. При выключении char-сервера остаток очереди тоже уходит в файл, при следующем старте файл доливается. Ничего не теряется.
4. Единственный случай двойного счёта: char-сервер упал ровно между «Mongo приняла» и «файл очищен» (доли секунды раз в 10 минут).

## Структура: база `uaro`, коллекция `online_daily`

Один документ = один персонаж за один день (дата по часам игрового сервера).

```js
{
  _id:        "20261121:150001",                // "YYYYMMDD:char_id"
  date:       "2026-11-21",                     // дата строкой
  day:        ISODate("2026-11-20T22:00:00Z"),  // полночь этого дня по времени сервера (в базе UTC); на нём TTL
  char_id:    150001,                           // int32
  account_id: 2000001,                          // int32
  name:       "Имя",                            // UTF-8 (в игровой базе имена в cp1251, сервер перекодирует)
  online:     187,                              // минут в игре, без автотрейда
  paid_buy:   60,                               // минут выкуплено @buyplaytime
  paid_auto:  42,                               // минут оплачено @autopay
  updated:    ISODate("...")                    // последнее пополнение
}
```

Индексы (сервер создаёт сам при первом подключении):
- `ttl_day`: `{ day: 1 }`, `expireAfterSeconds` = `onlinestat_ttl_days` × 86400 (365 дней);
- `char_date`: `{ char_id: 1, date: 1 }`;
- `account_date`: `{ account_id: 1, date: 1 }`.

Что учесть на сайте:
- документ за сегодня растёт весь день и отстаёт от реальности до `onlinestat_interval` (10 мин);
- нет документа = 0 минут в этот день;
- `online` и оплаченные минуты не складываются: игрок с `@autopay` весь день будет иметь, например, `online: 600, paid_auto: 600`.

Примеры:
```js
// неделя одного персонажа по дням
db.online_daily.find({ char_id: 150001, date: { $gte: "2026-11-15" } }).sort({ date: 1 })

// топ-50 по онлайну за 7 дней
db.online_daily.aggregate([
  { $match: { date: { $gte: "2026-11-15" } } },
  { $sort: { date: 1 } },
  { $group: { _id: "$char_id", name: { $last: "$name" }, account_id: { $last: "$account_id" },
              online: { $sum: "$online" }, paid_buy: { $sum: "$paid_buy" }, paid_auto: { $sum: "$paid_auto" },
              days: { $sum: 1 } } },
  { $sort: { online: -1 } }, { $limit: 50 }
])
```

## Настройка

- `conf/mongo_athena.conf`: база, коллекция, файл, интервал, срок хранения. Пароля там нет.
- `conf/mongo_conf.txt`: реквизиты, файл **не в git** (`.gitignore`), поэтому `DEPLOY.sh` (`git reset --hard`) его не трогает:
  ```
  onlinestat_mongo_uri: mongodb://ЛОГИН:ПАРОЛЬ@127.0.0.1:27017/?authSource=admin
  ```
  Нет `onlinestat_mongo_uri` → статистика выключена, в логе `[ONLINESTAT] online statistics are OFF`.
- Пользователю Mongo нужна роль `readWrite` на `uaro`.
- Сборка: при установленном `libmongoc-dev` (Debian: `apt install libmongoc-dev`) Makefile находит библиотеку через `pkg-config`. Без библиотеки сервер собирается, но пишет только файл и предупреждает об этом при старте.

Строки в логе char-сервера: `[ONLINESTAT] online statistics to ...` при старте, `MongoDB not reached (...)` когда Mongo недоступна, `MongoDB is back: N record(s) ...` после восстановления.
