# Дизайн SP1: бэкпорт базовых NPC новых городов

Дата: 2026-06-15. Ветка: `x64`. Источник: `/tmp/eathena-ref`.

Первый под-проект NPC-бэкпорта (см. декомпозицию в `prerenewal-maps-warps` памяти / разговоре). Покрывает
**только «городские» NPC** 4 новых локаций. Квест-цепочки — SP3 (после движка quest-лога SP2). NPC смены
3-х профессий, BG, инстансы — исключены.

## 1. Контекст и ключевой результат разведки

Разрыв скрипт-API между uAthena (313 команд, `BUILDIN_DEF`) и eathena-ref (388) = **81 команда**, но
**выделенные файлы 4 городов используют 0 из них**. Все используемые команды уже есть в uAthena;
синтаксис классический (`mes "...";`, `warp "map",x,y;`); `.@`-переменные поддержаны
(`src/map/script.c:2141/2187/2236`); `sleep/specialeffect/cutin` присутствуют. **SP1 не меняет движок.**

API-инвариант (не ломать действующие NPC) выполняется тривиально — изменений в `script.c` нет.

## 2. Объём SP1

**Портируем (дословно, координаты/диалоги/спрайты как в источнике):**
- `npc/cities/{moscovia,brasilis,manuk,splendide}.txt` — городские NPC, включая транспорт-входы
  (напр. «Moscovia P.R. Officer» в alberta; свободные `warp "moscovia"/"brasilis"`, не квест-гейтед).
- `npc/merchants/{manuk,splendide}.txt` — выделенные лавки Нового Мира.
- `npc/kafras/{kafras_mosk,kafras_brasilis}.txt`, `npc/guides/{guides_mosk,guides_brasilis}.txt`.
- Записи `moscovia` (2) и `brasilis` (4) из общего `npc/merchants/shops.txt` (извлекаются скриптом;
  у manuk/splendide лавки — в выделенных файлах, в shops.txt их нет; `inn.txt` для всех 4 пуст).

**Достижимость:** Moscovia/Brasilis — полностью в SP1 (свободный транспорт-NPC). Manuk/Splendide —
городские NPC портируются, но вход в Новый Мир квест-гейтед (`quests_13_1.txt`) → достижимость = SP3.

**Не входит:** `quests_*` (SP3), NPC 3-х профессий, BG/инстансы, остальные реневал-города
(Dewata/Malaya/Eclage/Dicastes/Malangdo — в этом eathena-ref у них NPC нет).

## 3. Подход

- Изолированное поддерево `npc/backport/{cities,merchants,kafras,guides}/` (зеркалит раскладку
  eathena-ref). Подключение — секцией в `npc/scripts_athena.conf` (`npc: npc/backport/...`).
- Выделенные файлы (10 шт.) копируются **дословно** с шапкой-маркером (источник, «не редактировать —
  это бэкпорт»). Записи `moscovia`/`brasilis` из `shops.txt` извлекаются детерминированным скриптом
  `dumps/forge/backport-town-npcs.py` (по аналогии с генератором варпов) в
  `npc/backport/merchants/shops_backport.txt`.
- Существующие NPC-файлы **не трогаются**. Движок **не меняется**.

## 4. Контингенция (на случай находок при верификации)

Ожидается 0 правок движка. Если верификация выявит используемую команду/синтаксис, отсутствующий в
uAthena: портировать команду в `script.c` **с сохранением старого API** (новый `BUILDIN_DEF` + реализация
в стиле uAthena `int buildin_x(struct script_state*)`), либо адаптировать NPC под старый API. Действующие
команды не менять.

## 5. Зависимости и риски

- **item_db.** Лавки продают предметы; их ID должны существовать в item_db uAthena (бэкпорт итемов
  добавил +2472). Отсутствующие ID → шоп ломается. **Митигейшн:** скрипт-отчёт по item ID лавок,
  отсутствующих в item_db — для задачи «итемы» (не блокирует SP1, но фиксируется).
- **Уникальность имён NPC.** Дубликат имени = ошибка загрузки. Проверка по всему `npc/` (вкл. backport).
- **Транспорт-NPC на существующих картах** (alberta и т.п.): тайл NPC не должен совпадать с действующим
  NPC. Проверка коллизий тайлов на не-backport картах.
- **Спрайты** — клиентские (GRF/деплой); сервер хранит ID.
- **Достижимость Manuk/Splendide** — ожидаемо отложена до SP3 (документируется).

## 6. Верификация (офлайн + тестировщики)

- Каждая скрипт-команда, используемая backport-NPC, присутствует в `buildin_func[]` uAthena.
- 0 дубликатов имён NPC по всему `npc/` (вкл. backport).
- Баланс `{ }` в каждом backport-файле; каждый NPC ссылается на зарегистрированную карту.
- Коллизии тайлов backport-NPC с действующими NPC = 0.
- Отчёт: item ID лавок, отсутствующие в item_db (список для задачи «итемы»).
- `git diff` показывает только добавления; ни один существующий NPC-файл не изменён.
- Полная загрузка карт/NPC и проход диалогов — фаза тестировщиков (нужны char-сервер + GRF; на дев-боксе
  карты не грузятся без GRF — как и в задаче варпов).

## 7. Раскладка файлов

- Создать: `dumps/forge/backport-town-npcs.py` (извлечение записей shops.txt + копирование выделенных
  файлов + отчёты/проверки; `--selftest`, `--verify`, `--items-report`).
- Создать (генер.): `npc/backport/cities/*.txt`, `npc/backport/merchants/*.txt`,
  `npc/backport/kafras/*.txt`, `npc/backport/guides/*.txt`.
- Изменить (append-only): `npc/scripts_athena.conf`.
- Создать: `doc/backport_sp1_town_npcs_changes.md` (сводка + чек-лист тестировщика + отчёт item ID).

## 8. Связанные под-проекты (вне SP1)

- **SP2:** движок quest-лога (`quest.c` + хранение на char-сервере + `db/quest_db` + 5 команд).
- **SP3:** квест-NPC нового контента (вкл. вход в Новый Мир для Manuk/Splendide), зависят от SP2.
- **SP4+:** mercenary-скрипт-API и прочие команды по мере надобности.
- Параллельно (другая задача пользователя): бэкпорт итемов (закрывает зависимость лавок).
