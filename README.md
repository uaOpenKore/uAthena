# Тесты uAthena (ветка `tests`)

Здесь только тесты и вспомогательные скрипты. Кода сервера в ветке нет. Тесты запускают настоящие login/char/map-серверы на отдельных стендах и играют за клиентов по сети: заходят в игру, бьют мобов, торгуют, перезапускают сервер и проверяют базу, файлы и логи.

> **Пути.** Пока в тестах прописаны абсолютные пути к рабочей папке, где они писались (`/tmp/claude-0/.../scratchpad/...`). Чтобы запустить их у себя, поменяй этот префикс на свою папку, например `grep -rl scratchpad . | xargs sed -i 's#/tmp/claude-0/-root-uaroClient/f1b47459-6a36-42ec-9fb0-528e8a9c2531/scratchpad#/opt/uatests#g'`. Перевод на переменную окружения — следующий шаг.

## Стенды

| Стенд | Что это | Порты | База |
|---|---|---|---|
| `e2e/run-t64`, `run-grav` | SQL-сборка (main), полный набор | 6900/6121/5121 | локальная MariaDB `ragnarok` (3306) |
| `sqlaudit/run-new` | SQL-сборка на изолированной базе | 16900/16121/15121 | отдельная MariaDB на 127.0.0.1:13306 |
| `txt/` (c1) | txt-сборка (ветка `txt`) | 16900/16121/15121 | файлы `save/` |

- Создание стенда: `sqlaudit/mkrun.sh <run> <worktree>`, `txt/mkrun.sh <run> <worktree>`.
- Запуск и остановка: `srv.sh start|stop <run>`.
- В тестовых конфигах Discord всегда выключен (mkrun проверяет, что вебхука нет).
- SQL-стенд и txt-стенд используют одни порты: одновременно запускать их нельзя.

## Что где

### `e2e/`: SQL-сборка, игровая механика и надёжность
- `run_suite64.sh`, `run_batch.sh`: основной набор (18 сценариев: вход/выход, перезаход, сохранение, мобы, таймеры, гравитация, буфер отправки и т. д.).
- Отдельные проверки: `run_s2sauth.sh` (сервер-сервер с чужого IP), `run_memtrim.sh` (память возвращается системе), `run_killexp.sh`, `run_connflood.sh` (лимит соединений на IP), `burst_e2e.py`, `npcview_e2e.py` (спрайты NPC для uaRO.exe и BornRok), `fuzz_*` (фаззинг пакетов), `streak_e2e.py`, `elemark_e2e.py` и др.
- `warp.c`: подмена монотонных часов (дни за секунды).

### `sqlaudit/`: SQL-аудит и новые механики (изолированная база)
- `regress.sh` + `regress.d/`: 30 сценариев SQL-аудита (инъекции, транзакции, потери данных, ошибки загрузки).
- `counters_e2e.py`: счётчики id за пределом; `idrange_e2e.py`: аккаунты до 1 млрд, id NPC от 1,1 млрд.
- `playlimit_e2e.py`: дневной лимит онлайна (счёт минут, предупреждения, кик через 40 с, GM, полночь, таймер 24 ч, рестарт, без миграции). `tools/wallwarp.c` подменяет системные часы.
- `autotrade_e2e.py`: лавки автотрейда переживают рестарт (17 проверок); `autotrade_load.py N`: замер подъёма N лавок.
- `*.sql`: подготовка данных для тестов.

### `txt/`: txt-ветка
- `login_e2e.py`, `persist_e2e.py` (42 проверки), `playlimit_txt_e2e.py`, `autotrade_txt_e2e.py`.
- `rostub.py`, `e2elib.py`: «клиент» на Python (логин, выбор персонажа, вход на карту, разбор пакетов).

### `livelogs/`: разбор прод-логов
- `padm.py`, `runs.py`, `tickrate_an.py`: метрики ботов и сессий из логов map.
- `botwatch_snapshot.py`: слепок «аккаунт — персонаж — IP» для слежения за фермами.

### `runners/full_regression.sh`
Полный регресс перед пушем: e2e, SQL-аудит, счётчики, лимит аккаунтов, лимит онлайна, автотрейд, txt.
- Порядок прогонов важен: стенды делят порты.
- Тест `charsel_latency` только замеряет время. Его FAIL с `rc=0` нормален.

## Правило
Каждая правка сервера идёт с тестом, который на старой сборке падает, а на новой проходит. Перед пушем — полный регресс обеих веток.
